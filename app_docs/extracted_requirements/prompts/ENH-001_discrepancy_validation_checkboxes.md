# Feature Prompt: ENH-001 - Individual Discrepancy Validation Checkboxes

Use this prompt with the `/feature` command:

```
/feature <issue_number> <adw_id> '<issue_json>'
```

## Issue JSON

```json
{
  "title": "Add individual discrepancy validation checkboxes in Riesgos module",
  "body": "## Problem Statement\n\nWhen discrepancies are found in the Riesgos module, Mesa de Control needs to validate them individually and mark each as reviewed with a specific reason. Currently, there is only a general confirm reviewed option with no ability to track which discrepancies were validated and how.\n\n## Current Behavior\n\n- Shows Confirme que reviso las discrepancias (Confirm you reviewed the discrepancies)\n- No ability to select/check individual discrepancies\n- PDF report shows Fallido, requiere revision even after manual validation\n- No audit trail of what was validated and why\n\n## Requested Behavior\n\n1. Display each discrepancy with a checkbox and validation reason field\n2. Allow user to mark each discrepancy as validated with a reason:\n   - Se valido manualmente (Manually validated)\n   - Se verifico que el correo esta correcto (Verified email is correct)\n   - Se cargo erradamente (Uploaded incorrectly)\n   - Justificacion del cliente aceptada (Client justification accepted)\n   - Custom reason option\n\n3. Update the evaluation status:\n   - When all discrepancies are validated: status = validated_by_mesa_control\n   - Partial validation: status = partially_validated\n\n4. Update PDF report to show:\n   - Validado por Mesa de Control instead of Fallido, requiere revision\n   - List which discrepancies were found\n   - Show validation reason for each discrepancy\n   - Include validator name and timestamp\n\n## Technical Requirements\n\n### Backend\n\n1. Add new fields to risk_cross_validation_results table:\n   - is_validated (boolean)\n   - validation_reason (text)\n   - validated_by (uuid, FK to user)\n   - validated_at (timestamp)\n\n2. Add new endpoint: PUT /api/risk/evaluations/{id}/discrepancies/{discrepancy_id}/validate\n   - Body: { reason: string }\n   - Returns updated discrepancy with validation info\n\n3. Add new endpoint: PUT /api/risk/evaluations/{id}/discrepancies/bulk-validate\n   - Body: { discrepancy_ids: string[], reason: string }\n   - For validating multiple discrepancies with same reason\n\n4. Update finalization logic:\n   - Check if all discrepancies are validated before allowing finalization\n   - Or allow finalization with unvalidated discrepancies but flag in report\n\n5. Update PDF export to include validation information\n\n### Frontend\n\n1. Create FKDiscrepancyValidationCard.tsx component:\n   - Checkbox for validation\n   - Reason dropdown with common options plus custom\n   - Show validator info after validation\n\n2. Update FKCrossValidationResults.tsx:\n   - Add validation checkboxes per discrepancy\n   - Add bulk validation action\n   - Show validation status indicators\n\n3. Update RiskEvaluationDetail.tsx:\n   - Add Validar Discrepancias section\n   - Show validation progress (2/5 validated)\n   - Enable/disable finalize based on validation status\n\n## Affected Files\n\n### Backend\n- backend/database/migration_add_discrepancy_validation.sql (NEW)\n- backend/src/adapter/rest/risk_routes.py\n- backend/src/core/servicios/risk/cross_validation_service.py\n- backend/src/repositorio/risk_repository.py\n- backend/src/interface/risk_dtos.py\n\n### Frontend\n- frontend/src/components/risk/FKDiscrepancyValidationCard.tsx (NEW)\n- frontend/src/components/risk/FKCrossValidationResults.tsx\n- frontend/src/pages/risk/RiskEvaluationDetail.tsx\n- frontend/src/services/riskService.ts\n- frontend/src/types/risk.ts\n\n## Acceptance Criteria\n\n- Each discrepancy can be individually validated with a checkbox\n- Validation reason can be selected from dropdown or entered as custom text\n- Validator name and timestamp recorded and displayed\n- Bulk validation available for multiple discrepancies\n- PDF export shows validation status and reasons\n- Final status changes to validated_by_mesa_control when all validated\n- Audit trail of all validations preserved in database\n\n## Access Control\n\n- Required Roles: mesa_control, risk_manager, admin\n- Only users with these roles can validate discrepancies\n\n## Priority\n\nHigh - Core workflow improvement for Mesa de Control team\n\n## Source\n\nFeedback meeting with Camila Perdomo (Mesa de Control) - December 29, 2025"
}
```
