## Problem Solved

**Initial Request**: After Legal approves contracts, Operations should be able to download the approved documents to send to customers for signature. Documents needed to be stored in Supabase Storage and made immutable.

**Issues Encountered**:
1. **Route Matching Error**: `/api/legal/contracts/approved` was being matched by `/api/legal/contracts/{contract_id}` route, causing UUID parsing errors
2. **Storage Bucket Error**: "Bucket not found" error when trying to download PDFs
3. **Public Access**: Bucket was private, preventing public URL access

---

## Root Causes

### Route Matching Issue
- FastAPI was matching "approved" string to `{contract_id}` parameter
- The parameterized route was trying to parse "approved" as a UUID, causing PostgreSQL error: `invalid input syntax for type uuid: "approved"`
- Even though `/contracts/approved` was defined before `/contracts/{contract_id}`, FastAPI wasn't distinguishing between them

### Storage Issues
- Supabase Storage bucket `contract-documents` existed but was **private**
- Public URLs generated by the backend couldn't be accessed without proper authentication
- Bucket needed to be made public for Operations to download files via URL

---

## Solution Implemented

### 1. Fixed Route Matching with UUID Validation

**File Modified**: `backend/src/adapter/rest/legal_routes.py`

**Changes Made**:
- Added `UUID` type import from Python's uuid module
- Added `Path` import from FastAPI
- Changed all `{contract_id}` path parameters from `str` to `UUID` type with validation

**Code Changes**:
```python
from fastapi import APIRouter, HTTPException, UploadFile, File, Depends, status, Path
from uuid import UUID

# Before:
@router.get("/contracts/{contract_id}")
async def get_contract(
    contract_id: str,
    service: ContractService = Depends(get_contract_service)
):

# After:
@router.get("/contracts/{contract_id}")
async def get_contract(
    contract_id: UUID = Path(..., description="Contract UUID"),
    service: ContractService = Depends(get_contract_service)
):
    contract = await service.get_contract_details(str(contract_id))
```

**Routes Updated**:
- `GET /contracts/{contract_id}` - Get contract details
- `GET /contracts/{contract_id}/preview` - Preview contract content
- `POST /contracts/{contract_id}/review` - Review contract (approve/reject)
- `GET /contracts/{contract_id}/download/docx` - Download DOCX
- `GET /contracts/{contract_id}/download/pdf` - Download PDF

**Why This Works**:
- FastAPI now validates that `{contract_id}` must be a valid UUID format
- Non-UUID strings like "approved" fail validation and don't match the parameterized route
- The specific `/contracts/approved` route is matched instead

### 2. Configured Supabase Storage Bucket

**Bucket Setup**:
- **Bucket Name**: `contract-documents`
- **Visibility**: Made **Public** for Operations access
- **Structure**: Files stored at `contracts/{contract_id}/{contract_id}_approved.pdf`

**Steps to Configure** (Already Done):
1. Created bucket in Supabase Dashboard → Storage → New bucket
2. Named it `contract-documents`
3. Made it **Public** via bucket settings (3-dot menu → Make public)

**Alternative (Private Bucket with Policies)**:
If you want to keep it private later, add RLS policies:
```sql
-- Policy for authenticated users to read
CREATE POLICY "Allow authenticated users to read approved contracts"
ON storage.objects FOR SELECT
TO authenticated
USING (bucket_id = 'contract-documents');

-- Policy for service role to upload
CREATE POLICY "Allow service role to upload contracts"
ON storage.objects FOR INSERT
TO service_role
WITH CHECK (bucket_id = 'contract-documents');
```

## Workflow Overview

### Complete Operations Workflow

1. **Legal Reviews Contract**:
   - Legal team reviews generated contract in Legal Dashboard
   - Clicks "Approve" button with optional notes

2. **Backend Processing** (Automatic):
   - Contract status updated to "approved"
   - DOCX document generated from template
   - DOCX converted to PDF using LibreOffice
   - PDF uploaded to Supabase Storage at `contracts/{contract_id}/{contract_id}_approved.pdf`
   - `approved_document_url` saved to database

3. **Operations Access**:
   - Operations team navigates to `/department/operations`
   - Views table of all approved contracts
   - Clicks PDF icon to download approved document
   - Sends PDF to customer for signature

### API Endpoints Used

- `GET /api/legal/contracts/approved` - List all approved contracts (Operations)
- `POST /api/legal/contracts/{contract_id}/review` - Approve/reject contract (Legal)

## Key Technical Decisions

### 1. UUID Path Parameter Validation
**Decision**: Add UUID type validation to FastAPI path parameters
**Reasoning**:
- Prevents route matching conflicts
- Provides better error messages
- Type-safe parameter handling
- Allows specific string routes like "approved", "stats", "pending-review"

### 2. Public Storage Bucket
**Decision**: Made `contract-documents` bucket public
**Reasoning**:
- Approved contracts are meant for distribution
- Simplifies URL access for Operations team
- No need for signed URLs or complex auth
- PDFs are immutable after approval

**Alternative Considered**: Private bucket with RLS policies
**Pros**: More secure, controlled access
**Cons**: Requires signed URLs, more complex implementation
**Decision**: Public bucket is appropriate for this use case

### 3. Automatic PDF Upload on Approval
**Decision**: Generate and upload PDF automatically when Legal approves
**Reasoning**:
- Ensures document is immediately available for Operations
- Prevents delays in workflow
- Guarantees PDF matches approved version
- Immutable storage for compliance

## Troubleshooting Guide

### Issue: "Bucket not found" Error
**Cause**: Storage bucket doesn't exist or incorrect name
**Solution**:
1. Check bucket exists in Supabase → Storage
2. Verify name is exactly `contract-documents`
3. Check SUPABASE_SERVICE_KEY has storage permissions

### Issue: "Access Denied" on PDF Download
**Cause**: Bucket is private without proper policies
**Solution**:
1. Make bucket public (Storage → contract-documents → Settings → Public bucket)
2. OR add RLS policies for authenticated access

### Issue: Route matching "approved" as UUID
**Cause**: UUID validation not applied to path parameters
**Solution**: Ensure UUID type is used in all `{contract_id}` parameters (Fixed in this session)

### Issue: PDF Not Uploaded After Approval
**Cause**: Upload failure during approval process
**Solution**:
1. Check backend logs for upload errors
2. Verify SUPABASE_SERVICE_KEY permissions
3. Check LibreOffice is available for PDF conversion
4. Review error handling in `contract_service.py:review_contract()`

## Code References

### Key Functions

**PDF Upload** (`document_service.py:393`):
```python
def upload_to_storage(self, pdf_bytes: bytes, contract_id: str) -> str:
    """Upload approved contract PDF to Supabase Storage"""
    file_path = f"contracts/{contract_id}/{contract_id}_approved.pdf"
    bucket_name = "contract-documents"

    response = self.supabase.storage.from_(bucket_name).upload(
        path=file_path,
        file=pdf_bytes,
        file_options={"content-type": "application/pdf", "upsert": "true"}
    )

    public_url = self.supabase.storage.from_(bucket_name).get_public_url(file_path)
    return public_url
```

```python
async def get_approved_contracts(self) -> List[dict]:
    """Get all approved contracts for Operations team"""
    response = self.db.table('contract_generations')\
        .select('*')\
        .eq('status', 'approved')\
        .order('reviewed_at', desc=True)\
        .execute()

    return response.data if response.data else []
```
