# Feature: Add Subsidiary and Retencion en Fuente Columns to Aplicacion de Pagos Mexico

## Feature Description
Add two new columns to the "Aplicacion de Pagos MX" (Mexico) output file generated by the Treasury/Tesorería payment template converter:

1. **subsidiary** - A static column showing the value `6` for every output row (Mexico subsidiary ID in NetSuite)
2. **retencion_en_fuente** - A column showing the withholding tax value ("Retención") from the input historial de pagos file, with special handling: when a single source row expands to multiple output rows (1:N expansion), the retencion value should only appear on the FIRST resulting row

This mirrors the Colombia implementation (issue #6) but with Mexico-specific values (subsidiary = 6 instead of 4).

## User Story
As a Treasury (Tesorería) department user
I want the "Aplicacion de Pagos MX" output to include subsidiary and retencion en fuente columns
So that I can upload payment applications to NetSuite with complete withholding tax information and correct subsidiary assignment

## Problem Statement
The current output template for Mexico lacks two important columns required by NetSuite:
- **subsidiary**: NetSuite needs to know which subsidiary the payment belongs to (Mexico = 6)
- **retencion_en_fuente**: Withholding tax amounts need to be tracked for accounting compliance, but should not be duplicated when a source payment row is split into multiple concept rows

Note: The `OUTPUT_TEMPLATE_COLUMNS` already includes these columns from the Colombia implementation (issue #6), but the Mexico-specific logic to populate them is missing.

## Solution Statement
1. Add `retencion` to `MEXICO_OPTIONAL_COLUMNS` in `payment_catalogs.py` to read withholding tax from input
2. Modify `_process_row()` in `payment_template_service.py` to:
   - Add `subsidiary: 6` to every output row when country is Mexico
   - Extract and pass retencion value to output for Mexico
   - Add `retencion_en_fuente` only to the FIRST output row generated from each source row (idx == 0)
