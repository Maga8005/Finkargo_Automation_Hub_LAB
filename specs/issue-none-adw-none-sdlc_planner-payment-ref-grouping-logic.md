# Chore: Adjust payment_ref Grouping Logic for Colombia Payments

## Chore Description
The payment_ref field in the NetSuite payment template output needs to be generated using a new grouping logic instead of reading directly from the "Código de recaudo" column.

The new grouping logic for generating the payment collection ID (recaudo ID) is based on the combination of four elements:
1. **Código de desembolso** (invoice_core_id) - The disbursement code
2. **Fecha de pago** (payment_date) - The payment date
3. **Moneda** (currency) - The currency (COP, USD, etc.)
4. **Cuenta Remitente** (cuenta_remitente) - The sender's bank account

For online payments ("Pago en línea"), where no bank account is registered, the currency is used to differentiate between payments going to different accounts (compensation account vs peso account). This logic applies to both online payments and other payment types.

**Current behavior:** `payment_ref` is read directly from the "Código de recaudo" column in the source Excel file.

**New behavior:** `payment_ref` should be generated by concatenating the four grouping elements, creating a unique identifier that groups payments with the same disbursement code, payment date, currency, and sender account.

## Notes
- The new `payment_ref` format should be consistent and deterministic so that the same input always generates the same grouping ID
- Consider using a separator that won't appear in the component values (e.g., `|` or `_`)
- The date formatting for the grouping key should use a sortable format like `YYYYMMDD` rather than the display format `DD/MM/YYYY`
- For "Pago en línea" transactions: since there's no bank account (cuenta_remitente is empty), the currency alone differentiates between COP compensation account and USD/other currency accounts
