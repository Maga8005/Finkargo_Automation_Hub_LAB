# Feature: Add Subsidiary and Retencion en Fuente Columns to Aplicacion de Pagos CO

## Feature Description
Add two new columns to the "Aplicacion de Pagos CO" output file generated by the Treasury/Tesorería payment template converter:

1. **subsidiary** - A static column showing the value `4` for every output row
2. **retencion en fuente** - A column showing the withholding tax value ("Retención") from the input historial de pagos file, with special handling: when a single source row expands to multiple output rows (1:N expansion), the retencion value should only appear on the FIRST resulting row

This enhancement ensures NetSuite compatibility by providing the required subsidiary identifier and proper withholding tax tracking.

## User Story
As a Treasury (Tesorería) department user
I want the "Aplicacion de Pagos CO" output to include subsidiary and retencion en fuente columns
So that I can upload payment applications to NetSuite with complete withholding tax information and correct subsidiary assignment

## Problem Statement
The current output template lacks two important columns required by NetSuite:
- **subsidiary**: NetSuite needs to know which subsidiary the payment belongs to (Colombia = 4)
- **retencion en fuente**: Withholding tax amounts need to be tracked for accounting compliance, but should not be duplicated when a source payment row is split into multiple concept rows

## Solution Statement
1. Add "Retención" as an optional input column in `payment_catalogs.py` for Colombia
2. Extend `OUTPUT_TEMPLATE_COLUMNS` to include `subsidiary` and `retencion_en_fuente`
3. Modify `_process_row()` in `payment_template_service.py` to:
   - Track the retencion value from input
   - Add `subsidiary: 4` to every output row
   - Add `retencion_en_fuente` only to the FIRST output row generated from each source row (idx == 0)

## Access Control
- Required Role(s): `tesoreria`, `admin`
- Backend Protection: Existing RBAC dependencies on `/api/tesoreria/*` routes already enforce tesoreria role
- Frontend Protection: Existing role protection on treasury pages (no changes needed)

## Testing Strategy

### Unit Tests
- Test that subsidiary=4 appears on ALL output rows
- Test that retencion appears ONLY on first row of each source row's expansion
- Test with rows that have no retencion value (should be None)
- Test edge cases: empty retencion, zero retencion, negative retencion

### Edge Cases
1. **No Retención column in input**: Output should have `retencion_en_fuente: None` for all rows
2. **Empty/blank Retención value**: Should be `None` in output
3. **Zero Retención value**: Should be `0.0` on first row only
4. **Single concept row (no expansion)**: Both subsidiary and retencion should appear
5. **Multiple concepts (1:N expansion)**: Retencion only on first row, subsidiary on all rows
6. **Separate SPREAD row**: Subsidiary on SPREAD row, but NOT retencion (SPREAD is a special case)
